ULP fold — behavioural audit against the operational code

Method. For every operational function the fold replaced, compare its actual code — statement by statement, including side effects, statement order, and the timing environment each statement runs in — against the fold implementation. Comments in main.c are not evidence: several are stale and three wrong root-causes on 2026-07-26 came from trusting them.

Coverage. Three independent passes: (A) regulate_pump / bp_drive_window / stop_pump; (B) AC service / sched_idle / entry-exit actions / park calibration; (C) an adversarial pass tasked with refuting A's first-draft findings. Line numbers were derived with grep -n/awk — the Read tool was observed silently dropping a 16-line block, which is why early drafts cited numbers 16 too low.

Status of the first draft: 1 of 4 clean. Corrections are recorded below rather than deleted, because the way they were wrong is the reusable lesson.

RANKED FINDINGS

Tier 1 — correctness / safety

1. The park stop-verify measures a de-energised, floating encoder

bp_park_complete disables BLOOD_PUMP_ENCODER_ENABLE_GPIO (2441) and then runs its 50 ms "did the rotor stop?" measurement (2446-2451). init_input (1311-1316) disables both pull-up and pull-down, so the pin floats throughout. Two branches, both wrong: a stable float ⇒ quiescent always true ⇒ bp_parked granted to a rotor that never stopped and the MOTOR_STOP_BP at 2461-2463 can never fire — precisely the silent success the check was written to eliminate; a noisy float ⇒ spurious fault on every park. Owner-confirmed working parks on dev.0.13 are consistent with the always-true branch. Fold-only code. CONFIRMED.

2. The DAC7574 is never re-asserted, and a reload can drive uncommanded

Op wrote the DAC unconditionally every batch (1839, 2356) and wrote DAC_HALT on every idle tick via stop_pump (1750, reached from 1936 / 2809). The fold writes only on change (2568-2583) and guards the idle HALT away (1933, 2804-2807). The software mirror becomes the only record of the hardware register, with no reconciliation. A swallowed write — I²C NACK, or SENS_IOMUX_CLK_EN gated across it (#48) — is now permanent; worst case a swallowed HALT leaves the motor driving while the mirror reads HALT, and both guards then refuse to re-issue it. Additionally, after a crash the CPU reloads fresh .data (bp_dac_value = DAC_HALT, 769-770) while the chip may still hold a driving value, and try_kick_pass raises enable_gpio (2630) ~1 ms before writing its own DAC value (2633) — a brief uncommanded burst at the pre-reset power. CONFIRMED. Owner decision 2026-07-26: change-gating is intended ("only write the DAC if regulation is needed"). The lost re-assert is therefore accepted, not a bug to undo — but seg_recover's explicit power-cycle is now the ONLY thing that can clear a latch.

3. TEST_DETERMINE_PARKING no longer pre-empts, and TEST_NONE no longer cancels

Op dispatched it at the top of main() before ac_tick/bp_tick, from any BP state (4822). The fold reads test_request only inside case BP_IDLE: (2769); there is no BP_RUNNING → BP_PARK_CAL edge. If the firmware writes the request while bp_pump_running == 1, the ULP never enters calibration, never writes TEST_NONE, and the firmware's documented poll blocks forever. Separately the fold's cancel check tests bp_park_calibrating (3327) and ignores test_request, so a CPU cancelling via TEST_NONE — the idiom every other test uses — cannot stop it; the motor drives to the 30 s deadline. CONFIRMED. This qualifies the "calibration contract proven end-to-end" claim: it holds only because the firmware happens to idle the BP first.

4. Stall de-duplication destroyed in RUNNING — ungated CPU wakes at ~3.6 Hz

Op latched the flag on the stall (*recovery_signaled = true, 1875) and passed a separate local start_signaled into the relaunch kick (1883-1886) specifically so the kick could not clobber the stall dedupe (its own comment, 1879-1881). The fold's stall branches (2878-2882 BP, 2033-2037 AC) contain the if (!..._recovery_signaled) guard with no assignment, and pass the shared flag into try_kick_pass (2129, 2734), which clears it on every successful kick (2658). A marginal pump then cycles stall → 200 ms recover → successful kick (clears flag) → stall at ~280 ms, emitting MOTOR_STOP_* + wakeup_main_cpu() ~3.6×/s where op emitted one per episode. The file's own SWR-289 note (2219-2228) records that ungated wakes latch the RTC CPU interrupt for the next lightsleep() — the #46 kill path, Fisher p≈0.02. CONFIRMED by all three passes. Dose/park omit the latch in op too — parity, not a regression; the regression is confined to the two RUNNING states.

5. Stale recovery_signaled can suppress fault reporting entirely

Op cleared it on every idle tick (2809 → 1747). The fold's guarded BP_IDLE never clears it, and bp_cal_halt (2473-2480) and the park-cancel (3121-3128) both leave it set. A later spin-up failure then hits if (!*signaled) == false ⇒ no MOTOR_START_FAIL_BP, no CPU wake, for the whole episode — a silently non-starting pump. CONFIRMED. This also means "only one escalation was logged" cannot distinguish "escalation stopped" from "escalation continued unreported".

6. Turn-on skip is per-ARM, not per-WINDOW ⇒ 1-edge start accept from window 2

s->skipped = 0 occurs only in the arm branch (2637); the escalation branch (2664-2680) re-arms only kick_deadline. So window 1 requires 2 rising edges and windows 2…N require 1. Op re-entered sample_encoder fresh each tick, enforcing its 3-edge bar on every window. A single noise edge then fakes a start → drive arms → no motion → stall → re-kick → escalate. CONFIRMED.

Tier 2 — robustness / battery

7. BP_DOSING past its deadline spins the core at 100% and blocks calibration

sched_idle returns false for BP_DOSING unconditionally (4733-4734). Once bp_dose_deadline passes, no branch drives, kicks, coasts or exits — the halt at 2967 is a no-op after the first pass and nothing clears bp_dosing (deliberate, 2968-2970). The do/while therefore never terminates: 100% duty against a ~24.9 mA budget until the CPU adjudicates. Op returned and slept. Chained: because test_request is served only from BP_IDLE (finding 3), a BP wedged here also blocks calibration forever. CONFIRMED (duration bounded by firmware; unbounded if the CPU faults with bp_dosing set).

8. AC service during BP moving states lost its rate limit, cap and dose-tail guard

Op's in-window AC slice was deliberately crippled: 1 per 16 BP windows (AC_BUSY_EVERY, ~0.8 s), a 150 ms hard cap (AC_BUSY_CAP_US), a 160-edge AC_BUSY_DOSE_GUARD so no slice could land on the dose target crossing, required ac_has_started, and it could not kick, stall-recover or walk the ladder (2204-2207). The fold runs the full ac_tick every pass (4841): it may kick (2015), power-cycle (2038), toggle the AC encoder enable (2028) and write the DAC anywhere, including on the last dose edge. The lost implicit guarantee is uninterrupted BP polling near the target. Mitigated by change-gated writes (2568-2583) and by seg_pass being a level comparator — at 16 s/rev (3.09 ms/edge, ~1.54 ms high phase) a 1 ms block cannot hide a rising edge. CONFIRMED DIVERGENCE; edge loss SUSPECTED and target-dependent (below ~5 s/rev the high phase drops under 1 ms).

9. Park-cancel is a partial stop

Op used the full stop_pump (3166-3170). The fold (3121-3128) halts the DAC and GPIOs but leaves has_started, recovery_signaled, integral_scaled, prev_error, max_power, min_power stale. A firmware park-cancel then carries bp_has_started == true into BP_IDLE. CONFIRMED.

10. bp_park_complete busy-spins 50 ms in the "nothing blocks" fold

2448-2451, with no bp_hall_edge_service and no ac_tick — a 50 ms blind window on both hall counters, once per park. Bounded (hall arcs ~1.2 s) but it contradicts the fold's headline claim. CONFIRMED DIVERGENCE.

Tier 3 — telemetry

  1. max_power/min_power never re-armed after a dose or park (guarded BP_IDLE at 2804-2807 never runs again), so per-run extremes become session-cumulative — and the fold added dose/park excursions to them via seg_pass (2566-2567).
  2. last_pulse_count frozen at 16, published only on a segment close (2561-2562); op published every batch including count == 0 (1821, 1900, 2348). The "0 pulses" stall signature is no longer observable by the host monitor.
  3. start_attempts and ac_busy_slices are permanently zero — their only increments (1794, 2294) are in functions with no fold call sites.

Tier 4 — documentation defects (these caused real wrong diagnoses)

  1. The op 1.18.0 changelog claims two fixes the binary does not contain. Entries (2) SANE HANDOVER and (3) DECAY at 512-517 describe kick_handover, which has zero call sites (declared 1921, defined 2698-2706) — withdrawn in dev.0.15 after it destabilised the AC. The escalation ratchet those entries claim to fix is still live, in both builds (fold 2670-2677, op 1711-1724 → bp_seed_pid 2103-2107). The ratchet is therefore NOT a fold regression.
  2. bp_tick's header (2423-2428) — "called once per main() invocation… ensuring AC is serviced again on the next invocation" — is the load-bearing statement about servicing cadence and is now false (it runs once per loop pass, 4842).
  3. DOSE_COAST_US is 1 s; comments at 567 and 3053 say 5 s. Full doc blocks remain for bp_drive_window (2298-2310) and ac_busy_regulate (2193-2207) which no longer ship.

CORRECTIONS TO THE FIRST DRAFT

  • F1 (stale step-4b comment) — conclusion right, evidence rotten. Cited 762-768 (unrelated declarations; the header is 1626-1650) and then "refuted a stale comment with a fresher comment". The load-bearing evidence is the absence of any de-energize in 1690-1728. It also audits dead code: try_kick_start ships in no regulating image.
  • F2 (start bar) — right, but understated. Op = 3 edges; fold = 2 only in window 1, then 1 (see finding 6).
  • F3 (kick edges lost to I²C) — REFUTED. A 50 ms kick window holds 16-50 edges and needs 2; at most one AC write (spacing ≥62 ms) can land in it; and seg_pass compares levels, so a 1 ms block cannot hide a 3.09 ms edge. Off by ~2 orders of magnitude. "Bit-banged" was also wrong — it is the RTC hardware I²C master. The "corroboration" only proved the AC was regulating. Survives only as finding 8's target-dependent suspicion.
  • F4 (stall_edge before the skip) — fact true, defect refuted, comparison false. seg_reset sets stall_edge on the same pass the encoder powers up (2525), so the discarded edge moves the deadline by milliseconds. And op does the same thing — sample_encoder sets seen_edge = true at 1389 before its skip check at 1390. Caveat retained: this holds for a dead motor. A rotor dithering against a hard spot emits edges, and those do keep refreshing stall_edge, which is finding 5's companion path.

CHECKED AND NOT A REGRESSION — do not re-investigate

  • Dose ledger edge accounting — both consume exactly 3 rising edges before counting resumes, including after a stall re-arm (op 1388-1397 + 2145; fold 2653-2660 + 2532 + 2551-2554).
  • Skip-ladder magnitude — op held N ticks, fold holds N ms, ULP wake period = 1 ms.
  • Hall wake gating — identical (op 2844, fold 4840); SWR-289 counting is unconditional in both, and the fold counts in more states.
  • sched_idle sleeping through the 200 ms recovery — op blocked with no hall service; the fold sleeps and still services hall each wake. Improvement.
  • Park "already home" latched at entry (2415) vs op recomputing per tick — fixes a boundary case where op skipped the centre offset. Improvement.
  • bp_enter_park_cal clears bp_parked (2497); op's test_determine_parking did not, leaving bp_parked == 1 while spinning off home. Improvement.
  • BP_PARK_CAL acceptance criteria — all nine present and identical, including the full-rev gate 4992..5376 and offset = bracket/2.
  • Entry-action state — has_started, recovery_signaled, first_update, integral/prev_error are cleared/seeded by all four entry helpers. Parity.
  • drive_armed, recover_until, skip_hold_until not cleared by some helpers — asymmetric but no reachable stale-flag path.
  • The merged seg_t.skipped field is safe across the kick↔drive split (no reachable has_started == false && drive_armed == 1). The unsafe sharing is within the kick phase — finding 6.
  • last_p_err_pct cross-pump — written and consumed in the same branch, AC strictly before BP. Safe.
  • No unsigned-underflow findings — rtc_ticks latches via TIME_UPDATE (no tearing); all deadline maths is monotonic uint64; the decrements and clamps are guarded.

PROCESS FINDING

The original parity check compared function lists and reported complete parity. It cannot detect a lost timing guarantee (finding 8), a missing assignment (4, 5), a reordered statement, or a check measuring a de-energised pin (1). Behavioural equivalence must be argued from code, per statement, with the timing environment included — and any diagnosis that will drive a code change must survive an adversarial pass, which here refuted the first draft's headline finding.
