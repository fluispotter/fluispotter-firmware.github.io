Multi Mode ULP

Status: Not implemented yet — design note only.

Concept

Keep two separate ULP RISC-V binaries on the MicroPython filesystem and swap them into ULP SRAM on demand, allowing a lean operational binary during normal use and a test-only binary during factory/diagnostic testing.

Proposed split

BinaryContents
pump_regulator.binac_tick, bp_tick, PID, dosing, parking — normal operation only
pump_test.binAll test functions (test_dac_sweep_enc, test_verify_encoder, test_resistance_map, test_determine_parking, test_fixed_power) — no PID loop, no state machines

Benefit: frees ~2–3 KB from the operational binary; the 8 KB ULP SRAM limit is tight.

Swap procedure (from MicroPython)

# 1. Safe shutdown — ensure pumps are off before swapping
machine.mem32[AC_PUMP_RUNNING] = 0
machine.mem32[BP_PUMP_RUNNING] = 0
time.sleep_ms(200)   # let regulation loop settle

# 2. Stop the ULP timer
ulp.stop()

# 3. Load new binary into ULP SRAM
with open('pump_test.bin', 'rb') as f:
    ulp.load(f.read())

# 4. Switch to the matching address map
from test_variables import *   # instead of variables.py

# 5. Start ULP
ulp.run()

Swap back to the operational binary the same way after tests complete.

Key design requirement — fixed shared-variable addresses

The biggest pain point is maintaining two variables.py-style address maps and keeping them in sync as the firmware evolves.

Recommended solution: use a custom linker script section to pin all shared variables to a fixed base address (e.g. 0x50001000) in both binaries. Both builds then share a single variables.py. Only the code sections differ in layout; the data interface is stable.

Example linker fragment:

SECTIONS {
  .shared_vars 0x50001000 (NOLOAD) : {
    KEEP(*(.shared_vars))
  }
}

Mark each shared variable in C:

volatile uint32_t ac_pump_running __attribute__((section(".shared_vars"))) = 0;

API Reference

Fluispotter device firmware for the ESP32-S3 with octal-SPIRAM.

Development API

The development module contains functions used for R&D and are meant to be run in the MicroPython REPL on the device.

All the *_sync functions have an async equivalent which require asyncio to run. It is possible to forcibly stop a sync function by issuing a keyboard interrupt with CTRL+C in the REPL. The program will try to cleanup as best as possible on an interrupt but there is no guarantee that it will end in a valid state, in that case soft reboot the device with CTRL+D.
