CI / Release Process Plan — Fluispotter Firmware & Software

Version 1.3 — 2026-06-12 — Status: APPROVED; Stage 0 + Phase 2 IMPLEMENTED

Stage 0 phase 1 shipped (2026-06-12): .github/workflows/ci.yml — lint (style frozen in .flake8, bug codes active), the SW verification suite (make verify → per-requirement report artifact), Monitor+Control offscreen smoke, and the version-bump discipline gate (.github/scripts/check_version_bump.py). Requirements registry + doc: verification/requirements.py → docs/fluispotter_sw_requirements.html (76 requirements, 64 SW / 12 MECH).

Phase 2 shipped (2026-06-12): ci.yml job ulp-build in the pinned espressif/idf:v5.3.2 container (matching the bench IDF v5.3.2) — idf.py build → output/build_verify_ulp.py (sizes/headroom/libgcc/versions for all three images; tool paths now env/PATH-portable in deploy_ulp.py) → .github/scripts/check_variables_drift.py (committed address maps must match the freshly built ELFs — the stale-address gate). Stage 1: .github/workflows/artifacts.yml (master + dispatch) builds the stamped firmware image + verified ULP binaries and generates release_manifest.json + SHA256SUMS + SBOM via .github/scripts/make_manifest.py (commit/submodule SHAs, every component version, toolchain, artifact hashes; dirty trees flagged unreleasable). KNOWN RED at introduction: the drift gate correctly reports test_variables.py/test2_variables.py stale vs source@HEAD (they predate the retain pinning; the board's old test binaries still match them) — cleared by one sanctioned deploy_ulp.py bench run.

Decisions (2026-06-12, Sten): (a) bench Mac WILL host a self-hosted runner with the board attached — YES; (b) releases move to master-only tagging — YES; (c) app packaging/signing (PyInstaller/notarization) — DEFERRED.

This plan defines a continuous-integration and release process covering all five shippable components in this repository, grounded in the build tooling that exists today. It is staged so each phase delivers value on its own.

Current CI gaps (found by audit, 2026-06-12)

  • No test or lint gate anywhere. make lint / make test (34 headless unit tests) exist but no workflow runs them. A v* tag releases firmware even if tests fail.
  • ULP is not in CI at all — the safety-relevant pump regulator is built and verified only on a developer machine.
  • No version stamping in CI (make stamp-version never invoked), no checksums, no signing, no SBOM, no record of submodule SHAs/toolchain in the release.
  • Reproducibility: unpinned setup-python version, floating action tags, pip install -r without hashes, ubuntu-latest drift.
  • Trigger asymmetry: docs deploy from master; firmware releases from any v* tag on any commit — releases are not tied to reviewed code.
  • Desktop apps: no packaging, no dependency pinning (>= floors), no tests, stale CFBundleVersion=1.0, launcher depends on the user's shell profile + a global Python.
  • Hardware-in-the-loop: all on-device verification is manual; mpremote drops this board (USB-CDC RTS), so any automated deploy must use the repo's pyserial raw-REPL tools (output/_serial_io.py, deploy_operational_serial.py, run_operational_convergence.py).

2. Target pipeline — four stages

 Stage 0  PR gate          every push / PR        (headless, GitHub-hosted)
 Stage 1  Artifact build   merge to master        (headless, GitHub-hosted)
 Stage 2  Bench HIL        nightly + pre-release  (self-hosted Mac runner + board)
 Stage 3  Release          v* tag on master       (gated on 0–2 evidence)

Stage 0 — PR gate (ci.yml, on every push + PR)

Fast, headless, no secrets beyond the submodule SSH key. All jobs required to merge.

  1. Lint — make lint; extend .flake8 coverage to monitor/ and control/.
  2. Unit tests — python3 -m unittest -v test/*.py (already passes headless in <1 s). Run the synchronize-service test suite from the submodule too.
  3. App smoke (offscreen Qt) — construct both MainWindows under QT_QPA_PLATFORM=offscreen on a Linux runner with pinned PyQt6/matplotlib/numpy; assert the window title contains APP_VERSION. (Verified feasible — both apps construct headlessly without a board.)
  4. Injected-script compile check — build every board_script.py factory output (MONITOR_SCRIPT, the three PID scripts, sensors, etc.) and compile() the emitted MicroPython. This is the static check that already caught splice errors; make it a permanent gate.
  5. ULP build + verify — idf.py build for all three binaries inside the pinned ESP-IDF container, then output/build_verify_ulp.py gates: no new libgcc, stack headroom ≥ 768 B, operational < 8192 B / test binaries ≤ 4592 B (runtime-load ceiling), version readable.
  6. variables.py drift check — regenerate the address map from the just-built operational ELF and git diff --exit-code against the committed one. Kills the stale-address bug class at PR time.
  7. Version-discipline check — if a PR touches monitor/** or control/** Python, require the matching app_version.py to be bumped in the same PR (simple script gate). Same rule for ULP: touching main/ulp/main.c requires a ULP_VERSION_* bump.

Stage 1 — Artifact build (artifacts.yml, on merge to master)

Everything Stage 0 builds, retained as traceable artifacts:

  • Full firmware image (firmware.bin) with make stamp-version applied first so the image embeds the git hash/build date.
  • The three ULP binaries + the regenerated variables.py / test_variables.py / test2_variables.py.
  • The rshell/pyserial-deployable .mpy bundle (make build output).
  • A release manifest (JSON): git SHA, all submodule SHAs, ESP-IDF + Python + toolchain versions, ULP versions (all three), APP_VERSIONs, spec-repo doc versions, SHA-256 of every artifact.
  • SBOM (pip freeze of the pinned env + submodule list).
  • Upload as a single versioned artifact bundle (retention ≥ 90 days).

Stage 2 — Bench hardware-in-the-loop (hil.yml, nightly + manual dispatch)

Runs on a self-hosted macOS runner (the bench Mac) with a devboard permanently attached. Uses only the repo's pyserial tools — never mpremote. Jobs are serialized with a bench-board concurrency group, and the workflow requires the Control/Monitor apps to be closed (check lsof on the port before starting).

  1. Deploy the Stage-1 operational ULP + firmware bundle (deploy_operational_serial.py pattern: copy, FNV byte-verify, reset).
  2. Convergence test — run_operational_convergence.py: AC @ SPR 20 and BP @ SPR 16 must converge (mean within ±5 % of target over the last N revs, motor_stop_events == 0, skip ladder climbing). This is the regression test for the Simple-P regulator.
  3. Sensor probe — veml_pressure_probe.py: VEML spot/line return non-zero lux, ADCs in range; flags the known pressure-saturation state.
  4. Publish a JUnit-style result + raw telemetry log as evidence artifacts; on failure, open a GitHub issue automatically.
  5. End state: board reset to normal firmware, LED rails off.

A pre-release HIL run is mandatory: the release workflow refuses to publish unless the candidate SHA has a green HIL evidence artifact.

Stage 3 — Release (release.yml, on v* tag)

  • Tag must point at a commit on master (enforced in the workflow) with green Stage 0–2.
  • Rebuild (or promote the Stage-1 artifacts of that exact SHA), attach: firmware image, ULP binaries + variables maps, .mpy bundle, release manifest, SHA256SUMS, HIL evidence bundle, and the spec-repo .docx files (generated in CI from the HTML via pandoc/libreoffice instead of macOS-only textutil, or attached from the repo).
  • Release notes generated from the manifest: per-component version table (firmware tag, ULP x3, Monitor/Control APP_VERSIONs, sync-service SHA, spec-doc versions) + changelog entries pulled from the app_version.py changelogs and spec change logs.
  • Docs: documentation.yml stays, but drop force_orphan: true so the Pages history is preserved, and pin the Python version.

3. Versioning & traceability model

One release = one release manifest that reconciles every independent version source. The git tag (vX.Y.Z) is the release version; component versions stay independent but are recorded:

SourceFileDiscipline
Releasegit tag v*tagged on master only
Build stampversion.pyCI runs make stamp-version; dirty-tree (*) builds are unreleasable
ULP (×3)main/ulp/main.cbump enforced by Stage-0 gate; deploy checklist stays
Monitor / Controlapp_version.pybump-per-change enforced by Stage-0 gate
Sync servicesubmodule SHArecorded in manifest; its own tests run in Stage 0
Spec docsHTML change logsrecorded in manifest

Reproducibility hardening (applies to every workflow): pin python-version, pin action tags to SHAs, pip install --require-hashes from a lock file, record the ESP-IDF tools digest, and verify submodule SHAs against the gitlink (no floating branches).

4. Component-specific work items

Desktop apps — make them releasable: pin app dependencies (== like the firmware requirements), add the offscreen smoke + a small unit-test seam for board_script factories and the sensors classify logic; later, package with PyInstaller (arm64) so the .app stops depending on /usr/local/bin/python3, the user's shell profile, and the repo path; sync CFBundleVersion from APP_VERSION at package time; sign + notarize when distribution beyond the bench is needed.

RPi synchronize-service — add its test suite to Stage 0; build a wheel in Stage 1; deploy to the hub via a tagged release + pip install (replacing the manual update queue) once the bench flow is trusted.

ULP/firmware — containerize the ESP-IDF build (image pinned by digest) so PR builds are fast and identical to release builds; keep check_ulp_memory.sh + build_verify_ulp.py as the single source of build gates.
