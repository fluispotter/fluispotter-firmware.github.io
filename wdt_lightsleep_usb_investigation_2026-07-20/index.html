GitHub #46 — WDT(3) at lightsleep entry: investigation record (WON'T FIX)

Closed 2026-07-20 by owner decision: bench-only artifact, requires an attached USB-CDC host. Production devices have no USB and are not exposed.

Mechanism

ESP-IDF's light-sleep entry flushes the console TX with interrupts disabled. With a USB-CDC host attached but not draining (a Mac with no terminal on the port — every bench session), the flush cannot complete, the interrupts-off window exceeds the 1000 ms IWDT timeout, and the SoC resets with cause 3. The firmware's own nap path wrote to that console on both sides of the sleep.

Campaign results

Campaign Firmware Sample-ends Fires Crumbs
1 0.1.119 50 (FINISH) 4 — (pre-instrument)
2 0.1.120 rev 3 ~20 2 10, 7
3 0.1.121 (radio gating) 40 3 12, 8, 12
4 0.1.122 rev 4 2 1 22 (inside machine.lightsleep)

Rate ~1 in 13 sample-ends throughout — the radio-gating fix (0.1.121) did not change it, which refuted the radio hypothesis honestly.

The discriminator

  • 44 h battery endurance run, USB DISCONNECTED: thousands of naps, zero watchdog resets.
  • Every USB-attached campaign: ~1 in 13 sample-ends.

Same firmware family, same nap code, same motors — the attached non-draining host is the only variable that tracks the failure.

Diagnostic infrastructure built (retained, permanent)

  • SWR-293 breadcrumb (ULP 1.14.0 cpu_breadcrumb + fw 0.1.120+): a CPU-owned word inside the ULP's mapped region, survives WDT resets, captured by the loader before the image reload wipes it, surfaced in the Boot: reset cause event as breadcrumb=<step>. Steps 1–13 name the site; 20–24 walk the nap path line by line.
  • Rev 1 (RTC user memory) was WITHDRAWN — it collided with the ULP and froze the parking path. Lesson recorded in the requirement: liveness ticks + canary are NOT sufficient to exonerate a shared-RAM write; the parking path must be exercised.
  • SWR-292 commit-before-IDLE: verified across all four campaigns — zero audit-trail loss through every reset.

Not fixed, deliberately

fw 0.1.123 (commit a76d64f, gate green, undeployed) implements the console-silent nap path + latched-sink veto. Deploy it only if quieter bench runs are wanted; it is not a product fix.

Bench protocol

Long USB-attached sessions will show ~1-in-13 self-recovered WDT resets. Recovery is exact and no data is lost. Detach USB for clean runs, or accept them.

Reopen if

A WDT(3) appears on a device with no USB attached — then read the boot event's breadcrumb and follow the step map.
